# CI and types move to Node.js 26 LTS

**Date:** 2026-10-30
**Source:** Claude Code (Sonnet 5.5), delegated from homebot
**Session:** Max asked (Telegram, 21:08) to move his active repos to Node.js 26, the new LTS (`v26.13.0` "Lithium",
2026-10-28). No merge, no release.

## Summary

CI and the release workflow now run on Node 26, and the root `@types/node` is `^26`. `engines.node` already read
`^22.11 || ^24 || >=26`; it stays, because the package is published and users on 22 and 24 must keep working.
No skill changed, so there is no changeset.

## What changed

- `.github/workflows/ci.yml` and `release.yml`: `node-version: 22` -> `26`.
- Root `package.json`: `@types/node` `^20.19.0` -> `^26.0.0`; `pnpm-lock.yaml` updated.

## Not changed: `evals/`

`evals/` (private, own lockfile, not part of CI) cannot install on Node 26: `evalite@0.19.0` (latest) depends on
`better-sqlite3@^11.6`, which ships no Node 26 prebuilt binary, and `node-gyp rebuild` fails. It installs on Node 24.
I left `evals/` as it was, including its `@types/node` `^22`. Fixing it means moving `evalite` off `better-sqlite3`
11 (upstream) or overriding to a newer major, and the evals need API keys that were not available to verify it.

## Checked on Node 26.13.0 (pnpm 10.27.0)

`pnpm test` (skills parse), `pnpm run validate` (all skills valid), `pnpm run test:council`,
`pnpm run typecheck:council`.
